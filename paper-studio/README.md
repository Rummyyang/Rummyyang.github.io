# 黑² · 论文与讨论

[公开入口](https://rummyyang.github.io/paper-studio/)由GitHub Pages托管，仅包含静态界面代码和公开资源。真实论文、讨论、口令及同步记录不存放在GitHub，也不使用Issues发表评论。进入工作台无需GitHub或ChatGPT账号。

工作台以专业、克制的研究协作为目标，角色名称统一为 **Codex／项目负责人／小小黑**。首页直接显示论文与旁侧讨论，导航只保留「论文／资料」。欢迎卡一键关闭，不要求输入口令；私密分享链接自动进入既有角色。历史、执行要点和管理操作集中于「更多」。可以按全项目或单篇论文回复、修改自己的意见，逐项查看待确认问题；未解决的旧轮次意见继续跟踪。

当前先推进两篇独立论文方案，第三篇为通过输入审计与成果边界核对后的条件候选。参考1已录用未见刊，参考2与参考3已发表。第一轮12项问题采用固定编号逐项回答，原始数据可后续分批补充。方案、初稿、假设、待核结论和补充工作须明确标注，不编造结果，也不将已发表或录用成果重复包装成新论文。

用户在原Codex任务中的明确指令优先，其次为项目负责人关键要求；未定细节主要参考小小黑反馈，由Codex核实并执行。没有明确决定不关闭轮次或开启下一轮。材料与成果保存具名版本；PDF可预览，TXT/Markdown可按段批注，DOCX可下载，也可对整份文件提交反馈。页面支持桌面和手机。

云端实际使用 **Vercel Functions + private Vercel Blob**：SQLite元数据快照通过CAS条件写入避免并发覆盖，稿件以私有对象和分片清单保存。当前API为 `https://xiaohei-paper-studio.vercel.app`，`cloud-config.json`只包含该公开地址；讨论和文件须经认证API访问。超过3 MiB的文件采用可续传上传，生产每片4 MiB、单文件最大300 MiB。

小小黑优先使用单独提供的reviewer私密邀请链接，已有访问短语仍可在访问设置中使用；owner和agent分别使用独立高熵密钥。不要公开真实短语、邀请链接或密钥。浏览器凭据暂存在当前sessionStorage会话，未提交草稿保存在本机，已提交内容以云端为准。

删除在应用层清空相应评论正文／锚点，或移除稿件的访问记录并删除私有文件对象；同步编号等必要记录保留。归档仍保存历史。删除失败需重试，不能据此承诺云服务商备份、日志或已下载副本零残留。

每小时接力在原Codex任务运行，通过后端项目的 `scripts/cottage.mjs` 拉取反馈、核查修订并回传实际成果；不会创建新的讨论任务。电脑、网络和Codex需要可用，离线后以实际补同步结果为准。未变化时不制造通知，只报告有意义的进展、完成、失败或需要用户处理的事项。具体执行规则见相邻后端项目的 `WORKFLOW.md`。

## 当前阅读与反馈方式

默认打开论文一的中文PDF DEMO；选择论文后可切换中英文或真实存在的历史稿件版本。中文为完整文章形态示意稿，英文为标题与摘要单页，均标注DEMO和证据状态，不能视为投稿稿。PDF.js 5.6.205从本地静态资源加载，经认证取得PDF字节后在浏览器绘制，不调用外部文档阅读服务。支持翻页、整页／适宽、展开阅读与下载。段落批注仅在文字稿的展开阅读中按需打开。

「现在做什么」显示当前最需要回复的两项，并提供共用材料入口。待确认问题通过受认证 `/api/questions?round=N` 全量读取，独立于留言分页；收到回复不等于核验完成。未提交草稿按身份、轮次、论文分开保存，切换语言或稿件不清空草稿。手机提供直接到留言区的入口。

品牌为黑²（黑哥×小小黑），使用克制的奶油白、炭黑和浅桃色。欢迎卡及讨论旁保留田曦薇甜美气质灵感的学习伙伴插画，不代表本人参与或代言。
