04

后训练与 Reasoning 核心讲义

首次接触这个方向，可先读Adaptive Thinking 领域导读与最新研究。先口头回答核心问题，再展开核对。这里只保留面试所需的概念骨架；论文动机、方法、实验条件与限制见完整讲义。

让策略依据输入 x、当前模型能力、可用预算 B，以及可选的生成中状态，决定是否展开显式推理、使用何种推理方式、何时结束思考。核心是学习条件化的计算分配，而不是把所有回答统一缩短。

先辨析：模式、预算、路由、early exit 与隐藏推理
概念谁决定、何时决定与自适应计算的关系
固定 token budget由调用者统一给上限 B，或按预设规则给每类问题不同 B。是资源约束/控制接口；预算内自然提前结束不自动证明模型学会最优分配。

s1 的 budget forcing；Qwen3 报告中的阈值到达后插入 stop-thinking 指令。

thinking / non-thinking 模式切换同一模型能够按控制信号输出长思考或直接答案。是可控能力；如果模式由用户指定，仍没有解决自动选择。

初代 Qwen3 /think、/no_think 与 enable_thinking。

学习型 adaptive thinking模型/控制器依据题目与预算预测模式，并通过训练学习质量—成本取舍。可以用单模型首 token、独立控制器或生成中停止策略实现。

Thinkless 学首控制 token；本方案再研究预算条件下的停止时机。

early exit术语需先澄清：一是思考序列提前终止，二是每个 token 跳过后续网络层。前者改变生成长度，后者改变每 token 计算深度；都可能自适应，但不能混称。

本方案只研究停止显式思考，不改变 Transformer 层数。

router / cascade外部系统选择小/大模型、直接答/深度推理，或失败后升级。router 是机制；训练得到的 router 也可实现自适应计算，但需把路由、重试和多模型成本计入。

本方案把同一学生上的轻量模式 router 作为公平基线。

hidden reasoning把生成的推理内容不显示给最终用户。这是可见性设置；隐藏了文本并不免除生成 token、KV cache 和延迟。不要由输出没有 think 标签推断没有内部推理。

区分原始生成 token 与最终可见 answer token。

latent reasoning在连续隐藏状态等内部表示上做额外计算，而非逐步输出自然语言推理 token。这与把文本 CoT 隐藏显示是不同概念；本次实验不引入新的 latent 架构。

作为面试术语边界理解，不纳入两周最小实验。

模型插值的全局 λ用验证集选定一组模型权重，在部署时使用该单模型。可移动整体质量—长度取舍，但全局 λ 本身不保证逐题最优预算分配。

Revisiting Model Interpolation for Efficient Reasoning 可作为强且便宜的对照。

我会先确认团队所说的 adaptive 是用户可控、请求级自动选模式，还是生成中动态停止。我的研究兴趣是后两者：在明确质量约束下，把计算花在有收益的问题和阶段上，而不是只减平均长度。

01 · 先画清训练链：预训练、SFT、蒸馏、RL

每个阶段到底改变了什么，何时需要它？

预训练提供语言与知识基础；SFT 学参考响应与输出行为；蒸馏引入教师的轨迹或软分布；RL 按可验证结果/偏好重新分配轨迹概率。SFT→OPD→RL 是一个候选配方，不是必需定律。R1-Zero 说明可从合适基座直接 RL，R1/Qwen3 则说明冷启动与多阶段训练的实用价值。

白板表达

L_SFT=−E_(x,y*) Σ_t log πθ(y*_t|x,y*_<t)；只对 assistant 目标 token 算损失，明确 sum/mean、padding 与 EOS。

SFT 为什么可能改变后续 RL 探索？

它改变初始轨迹概率与熵；硬拟合少数参考可能提高即时答案分数，也可能压低可探索替代路径。必须测后续 RL 终点。

何时用 SFT，何时优先 RL？

格式/行为尚未可用、有效 rollout 稀少时先建可学起点；已有可解覆盖且 verifier 可靠时 RL 更有直接信号。看小规模诊断而非固定口号。

DPO 与 GRPO 怎么区分？

DPO 用成对偏好优化相对概率；GRPO 从策略采样得到组内奖励差异。比较时要明确偏好数据是否离线、是否使用 reference、以及生成成本。

回到自己的论文

  • Shadow-FT：用‘在何处学习参数增量’解释后训练行为与新任务学习的相互影响。
  • ProFit：用‘哪些参考 token 产生梯度’连接 SFT 数据价值，不能把高概率当作通用语义重要度。
  • Simple-OPD：用预热初始化解释阶段间兼容性；个人负责模块需用户自行补充。

02 · 白板讲透 GRPO、DAPO、GSPO

同样的最终答案奖励，为什么优化实现会改变稳定性和长度？

先固定 rollout 行为策略、参考策略、reward、advantage，再逐项比较 ratio、clipping、长度归一化和样本过滤。GRPO 的组内对比减少 critic 成本，但仍会遇到同奖组、长链 credit assignment、策略陈旧和熵坍塌。DAPO 与 GSPO 分别改变这些环节，不能只背缩写。

白板表达

r_it=πθ/πold；A_i=(R_i−Rbar)/(std(R)+ε)；clip surrogate=min(r_it A_i,clip(r_it,1−ε_l,1+ε_h)A_i)。A<0 时要能解释 min 为什么限制另一方向的更新。

πold 与 πref 一样吗？

πold 是采样行为策略/近端更新锚点；πref 是正则参考。二者可按配方更新，但职责不同。

全组都答错还能学什么？

仅同一结果奖励的组内优势为零；KL/其他奖励项可能仍更新。需改善题目可解性、增加有效采样或提供预热，而非假装有正确性梯度。

为什么不能说 PPO clipping 保证 KL 不超过阈值？

clipped surrogate 只限制部分样本的目标激励，不是硬 KL 约束；仍应监控实测 KL、ratio 分位数和 clip fraction。

GSPO 的 s_i 是标准无偏 IS 权重吗？

完整序列比值才对应原始变测度恒等式；长度归一化与 clipping 是稳定训练的 surrogate 设计。

回到自己的论文

  • Simple-OPD：解释更合适的初始化如何增加有效 RL 组；这仍需新实验证明。
  • Model Interpolation：用 Mean/Pass 与熵区分可靠性和探索覆盖，避免混为同一能力。

03 · OPD：谁生成前缀，如何匹配分布，何时停止预热

为什么用学生自己生成的序列，却仍能从教师学到更多？

学生在自身 prefix 上得到教师反馈，缓解只跟随教师轨迹训练时的访问分布差异。prefix 来源与 FKL/RKL 是独立选择；局部 full-vocabulary KL、top-k 近似和 sampled-token 估计也要分开。先比较相同教师、数据与预算，再讨论适合即时分数还是后续 RL。

白板表达

设 p=student，q=teacher：FKL=Σ_v q_v log(q_v/p_v)，RKL=Σ_v p_v log(p_v/q_v)。完整轨迹 KL 的链式法则要求外层轨迹采样分布匹配且不额外逐序列长度归一化。

OPD 是否就是 reverse KL？

不是；OPD+FKL 也是合法组合。

GKD 是否对采样过程反向传播？

原文不对学生采样分布回传；在采到的 prefix 上优化局部分布匹配。不要把这写成完整期望目标的全部梯度。

什么情况下蒸馏教师太强反而不合适？

能力、tokenizer、思考格式与访问状态差异可能使监督难以利用。更强教师不自动最兼容。

为什么不直接加大 LoRA rank/预热轮数？

适应性与域外保留可能冲突；需要验证集确定近饱和点，并把后续 RL 与总算力纳入评价。

回到自己的论文

  • Adaptive KL：动态调局部散度权重；需强调 head/tail 误差加权的是两个完整 KL。
  • LLM-NEO：减少可训练参数的优化器/梯度成本；教师前向和学生激活仍存在。
  • LoCa：校准监督分布可减少教师错误方向，但生成任务多解时不能机械强制唯一 token 最高。
  • Simple-OPD：解释 teacher-compatible warm-up 与后续 OPD 的连接。

04 · 训练何时想、想多久

如何从可手动切换两种模式，走到模型自动分配计算？

先保证短答/长思考都可用，再让策略学习模式首 token；通过正确性—成本奖励学习选择，并让停止 token 参与响应策略优化。用户预算作为上限或条件输入。模式决策与长响应的梯度尺度应分别监控，避免只学一种模式。

白板表达

π(m,y|x,B)=π(m|x,B)π(y|x,B,m)；Thinkless 把 mode surrogate 与 response surrogate 分别归一化。预算上限 B 和实际长度 T 是两个变量。

为什么不根据问题字数直接分配预算？

字数与所需计算不等价；短题也可能难，长题也可能只是抽取。规则可作基线，学习策略应在跨域/改写测试中证明收益。

用户指定 think 时还应自动选择吗？

把用户模式要求设为约束；自适应策略在允许的范围内选择深度。产品控制与模型策略的优先级应明确定义。

怎样证明模型学的是收益而不是题目表面样式？

使用等难度改写、领域外题、短难题/长易题切片；比较按额外思考真实增益分桶的分配，并限制只用部署可获得的特征。

回到自己的论文

  • Model Interpolation：全局 λ 给出无需新训练的取舍基线；下一步才是逐题、逐预算条件化。
  • Timber：可用现有检查点调整探索性，但 eRank/熵都只是代理，不是自适应策略已正确的证据。

05 · 正确性、长度奖励与难度混合

怎样让模型学会高效正确，而不是更快地答错？

把正确性与成本分开测，保留短错作为负例，明确截断样本如何计奖。难度取决于当前学生在每种模式下的可解概率；全难可能无正例，全易可能全同奖。训练要保持可学的对比，并记录重采样成本。

白板表达

若独立采样、单次正奖率 p、每题 G 次：P(至少一个正例)=1−(1−p)^G；P(正负混合组)=1−p^G−(1−p)^G。增加 G 不自动提高单次成功率 p。

reward=correct−λ×length 有什么坑？

尺度不匹配会诱导短错；不同预算和数据难度下 λ 的含义变化。需归一化成本、验证质量下限，画不同 λ 的 Pareto 曲线。

mask 掉错误回答不是更干净吗？

会移除区分短错与短对的信号；在有正例的组中，错误零奖本来可以获得负优势。

难题比例越高越好吗？

不一定；先诊断各模式成功率和有效组比例，再做 easy/hard 混合与课程消融。

回到自己的论文

  • ProFit：选择 SFT token 与选择 RL 轨迹是不同层级；不能把 ProFit 掩码直接等同于丢弃负回报。
  • Quantization Meets Reasoning：错误定位与针对性修复提示保留失败类型诊断；压缩后预算策略也可能需要重校准。

06 · 证明收益：固定预算、质量—成本前沿与无泄漏

你如何证实变短是可用改进，而不是指标选择造成的幻觉？

至少同时报告统一请求上限下的单次质量、相同平均总 token 成本下的质量前沿、相同硬件负载下延迟、困难/OOD 切片。长度统计包括全部生成，Pass@k 只作覆盖诊断，并计 k 次成本与选择器成本。

白板表达

支配定义：方法 A 的质量不低、成本不高且至少一项严格更好，才支配 B。Pareto 前沿不能用单一 accuracy/token 替代。固定总预算时多次采样与单次长思考也应统一成本。

Mean@k、Pass@k、Vote@k 分别说明什么？

Mean 是采样正确率平均；Pass 是至少一次正确的覆盖；Vote 是实际投票策略质量。Pass 使用 oracle 判定，不能当成部署用户拿到的准确率。

为什么 AIME 小幅提高不一定可靠？

题数少、采样和训练种子都会波动；应按题 bootstrap，并把 checkpoint 内采样方差与多次训练方差分开。

验证集应该选择什么？

只在验证集选 λ、mode 阈值、预算、checkpoint 与插值 λ；锁定后一次评测测试集。不要反复用测试曲线筛选最佳点。

回到自己的论文

  • Model Interpolation：保持 Mean、改善 Pass 和降低 token 是不同证据；token 降幅不是实测硬件加速比。
  • FluxBin：算法层的成本代理必须落实为相同硬件、负载、质量条件下的真实性能。
  • LLMs on Memristors：区分估算能耗与真实硬件测量；高噪声长复读会改变成本分布。

07 · 可验证训练数据与奖励可靠性

没有可靠 verifier，如何知道你训练出了推理能力？

数学/程序执行适合作为初步可验证域；开放式任务需另做评分与人工审计。解析失败、答案格式投机、测试覆盖不足和数据重复都会污染训练。数据质量要同时看题目可解性、参考正确性、难度覆盖与近重复。

白板表达

将解析有效性、答案正确性、格式、成本分别记录。主质量奖励来自正确性验证；格式不能替代正确答案，LLM judge 分数不能直接当真值。

代码通过测试就一定正确吗？

有限测试只能提供证据；增加隐藏边界测试与变形测试，避免公开测试被硬编码利用。

如何向零售场景扩展？

先用可程序生成与验证的规则组合、优惠计算、约束选择作为公开代理任务；它们只是建议场景，不代表京东内部任务或数据。

怎么审计泄漏？

按题源/模板/时间先划分，再做文本与语义近重复、题解派生和共享生成模板审计；新生成不保证与公开 benchmark 无关。

回到自己的论文

  • LoCa：标签可信度决定监督校准是否合理。
  • Quantization Meets Reasoning：从 unique_id 排重扩展到语义重复、题解污染与强教师生成审计。

08 · 训练系统与部署成本：从 token 到延迟

后训练主要花在哪里，推理少 token 为什么不总是等比例更快？

训练拆成 rollout、教师/奖励前向、actor backward、权重同步与排队；长尾响应和 stale rollout 会同时影响效率与算法。部署拆成 prefill、decode、KV cache 与调度。与用户的量化工作相接时，分别测每 token 速度和总生成量。

白板表达

延迟≈排队+prefill+逐 token decode+工具/验证时间；这只是测量分解，真实 batch、缓存和并行使每 token 成本不固定。

LoRA 为什么未必显著降低 OPD 总成本？

优化器/梯度变小，但教师 logits、学生生成和长序列激活可能占主导。先做时间与显存分解。

异步 rollout 的代价？

吞吐可能更好，但行为策略更陈旧；需保存生成 logprob/版本，监控 ratio、有效样本与性能。

隐藏思考时 TTFT 怎么报告？

同时报告模型首生成 token、首个可见答案 token、端到端完成时间；只报不可见思考的 TTFT 会误导用户体验。

回到自己的论文

  • LLM-NEO：把参数效率与整个流水线显存/时间分开。
  • PTQTP：真实压缩格式与缩放开销，而不是只说理论位宽。
  • FluxBin：算法与 kernel 协同，统一硬件与 batch 后比较。
  • LieQ：位预算分配与思考预算分配都需质量约束；结合是待验证设想。

用 90 秒讲清这项研究设想

我会把自己现有的蒸馏和高效推理工作连接起来：先让同一学生学会短答与长思考，再在学生自身前缀上做模式条件化 OPD，最后用正确性与生成成本训练何时思考及停止。主张必须由固定 token/延迟预算下的质量前沿支持，并检查困难题与域外能力。最关键的对照是总成本匹配的 SFT→RL、固定预算和轻量 router；如果 OPD 的准备成本抵消部署收益，结论也应如实报告。

  • H1：适量同教师预热加 OPD 比只用硬标签 SFT 更能保留两种模式的有效候选，提升随后预算 RL 的样本效率。
  • H2：将模式决策与响应的损失尺度分开，可减少模式坍塌；长度成本使已选 think 模式学会更早完成，而非一律 short。
  • H3：easy/hard/暂不可解混合比只训难题更稳定；但简单全对组比例过高也会削弱对比。
  • 这些是假设；不能以论文之间可以拼接为由声称效果必然叠加。
最小实验：模型、数据规模与资源边界

学生

首轮建议 Qwen3-1.7B 初代混合模型；若资源允许再扩 Qwen3-4B。固定具体 revision、tokenizer 与模板。

教师

同 tokenizer 家族的 Qwen3-8B 作为低成本试验教师；资源允许可换 Qwen3-32B。固定 checkpoint，明确每种模式的提示。

选择依据

使用同词表方便完整 token 分布对齐；模型选择是可行性建议，不是已测得最佳组合。

预算条件

B∈{512,2048,8192} 个总新 token 为初始候选；B 是输入预算条件和硬上限。为最终答案预留可调固定窗口，reasoning 与 answer token 都计入成本。

先做资源试测

先测 50–100 条的峰值显存、tokens/s 与教师 logits 开销，再决定 batch、序列长度与并行；不在不知道 GPU 的情况下承诺两周完整大规模训练。

首轮规模

2K–5K 训练题、500 验证题、锁定测试集；先单 seed 调通，再对最终少量配置做 3 seed。数据规模和种子数均为建议。

数据、难度分层与防泄漏

候选任务

  • 公开数学/可执行代码，先只做规则 verifier 可靠的子集。
  • 可选零售代理任务：由程序生成的优惠叠加、库存/配送约束、规则组合；不使用或假定存在京东内部数据。

划分顺序

按题源、模板族和派生关系先划分 train/validation/test，再生成答案；train 内另划 SFT/OPD 与 RL 提示池，便于分析准备与后续学习。

相对于当前学生的难度

仅用训练池，在学生 short/think 两种模式各采样少量候选，估 p_short、p_think；标为两模式可解、仅长思考相对可解、当前均难。难度不是题目永久标签。

难度混合

初始可试 40%两模式可解、40%长模式相对可解、20%当前难题，并与均匀/只易/只难对照；比例只是试验起点。

泄漏检查

  • 同题不同解法、改写与模板同族放同一 split。
  • 文本 exact/near duplicate 加语义相似人工抽查；追踪题解来源与教师生成记录。
  • 最终评测题不用于难度路由标签、奖励调参、checkpoint 选择或模型插值 λ 选择。
  • 只用训练/验证集建立 router；部署不可访问参考答案或评测 verifier 的事后结果。
A · 双模式 SFT 预热

操作

用同一教师分别生成短答与长思考，验证最终答案；成对成功样本形成清晰模式映射。只有长答正确的题保留长模式样本，不伪造短答正确标签。用适量 LoRA 预热，独立验证集选近饱和点。

目的

让模式 token 可控并保留两种能力；记录模式遵循率、分模式准确率、熵和域外保留。

消融

无预热 / 硬标签双模式 SFT / 同教师与异教师 SFT；rank 与时长仅做小范围对照。

边界

错误 CoT 的预热效果可列研究消融，不能当主方案的正确答案监督。

B · 模式条件化 OPD

操作

给定外部采样的模式 m 与预算条件 B，学生生成自身响应 prefix；教师在相同 prefix 与模式下提供 logits。主比较 FKL/RKL，AKL 作为与现有论文连接的选配消融；固定教师、数据、rollout 和优化预算。

目的

让学生在自己会访问的状态得到密集反馈；比较预热后即时分数与后续可学习性。

目标

L_OPD=E_(x,m,B), y~stopgrad(πS(.|x,m,B))[(1/T)Σ_t D(pT(.|h_t,m,B),pS(.|h_t,m,B))]。

边界

强制抽样 m 时，这是条件响应策略的 on-policy distillation，不能宣称整套自动模式策略也完全 on-policy。不要用未校正的强制模式 rollout 更新 joint-mode policy gradient。

C · 学习模式选择和思考停止的预算 RL

操作

模型自行采样模式首 token，在预算 B 内生成响应；think 模式中由原生停止思考 token 决定何时进入答案。先采用可解释的 GRPO 风格实现，对 mode 与 response 的 surrogate 分开归一化；响应部分包含停止 token。和不分开的实现对照。

奖励

初始奖励 R=1[verified_correct]−λ·min(T_total/B,1)，0≤λ<1；再按验证质量约束选 λ。截断/解析失败记为未完成，单独统计，不误标为‘推理逻辑错’。

这个奖励能保证什么

该 λ<1 只保证在此有界标量奖励中任何正确轨迹得分高于任何错误轨迹；它不保证整体策略不会为成本牺牲准确率，因此仍需总体与困难切片质量下限。

成本口径

T_total 包括所有思考、最终答案与重复生成，防止把思考搬进答案来规避成本。部署时另测延迟；不要假装 token 是硬件无关的真实时间。

优化对照

主方案只保留一种清楚的 loss reduction。DAPO 的全 token reduction、GSPO 序列 ratio 作为后续独立对照，不一次混进多个改动。

需要记录的指标

  • 按模式的成功率、选模比例与熵
  • 四类：短对/长对/短错/长错
  • 同奖组比例、clip fraction、ratio 分位数、KL
  • 截断率、长度 p50/p95、reward 与验证质量
  • rollout 策略版本、staleness、训练总 token/GPU hours
强基线与公平比较
  • 同 checkpoint 的 always short 与 always think，在完全相同推理参数与总新 token 上限下。
  • 外部固定预算/早停控制；另用 s1 风格延长作为可选预算曲线对照，不能只选一个弱预算点。
  • 同一学生上的轻量 router 或预算规则；训练数据与路由额外延迟计入。
  • SFT→RL、SFT→OPD→RL、无 OPD 但用省下算力延长 SFT/RL：分别报告相同下游预算和相同总训练预算两种比较。
  • 全局模型插值基线（仅限权重坐标兼容的模型）；在独立验证集选 λ，记录选择开销。
  • 事后 oracle 选择模式仅作为诊断上界，明确它用到了正确性信息，不能作为可部署基线。
  • 多次短采样/投票或 verifier reranking 只有在计入全部采样与选择器成本后，才能与单次长推理比较。
评估协议：什么结果才支持“更高效”

主要指标

固定每请求 cap B 的单次答案质量；同平均总生成 token 成本下的 quality–cost Pareto frontier。每条曲线只用验证集选择超参数/阈值，再冻结测试。

真实延迟与吞吐

在同一 GPU、引擎 revision、精度、batch/concurrency、prompt 分布、KV cache 与 warmup 条件下，测 p50/p95 端到端、首可见答案时间、吞吐；单请求和并发负载分开。

质量切片

easy / hard / 当前不可解、数学 / 代码 / 代理业务、短难题 / 长易题、OOD、不同预算；同时报告模式覆盖和截断率。

覆盖诊断

Mean@k 与 Pass@k 用于质量/覆盖诊断；主部署指标是实际选出答案的正确率，不把 oracle Pass@k 冒充可实现准确率。

不确定性

最终配置尽量 3 个训练 seed；按题 paired bootstrap 报告质量差与成本差区间。小 AIME 样本不单独承担结论。

总训练成本

记录教师数据生成、筛选验证、SFT、OPD、RL 和参数搜索的总 GPU hours / token /显存；不能只报告最后 RL 的步数。

事先确定接受条件

研究性预设示例：验证后锁定约 1 个百分点总体质量容忍度，并给 hard/OOD 单独下限；若达到质量下限再讨论平均 token 或 p95 延迟下降。1 点是建议阈值，需按具体任务要求调整。

不能据此声称有效的比较

  • 只减少思考标签内 token，却把长文本移到最终答案。
  • 只比较各方法最佳一次训练，隐藏种子波动。
  • 用更大生成上限/更低温度帮助某个方法而未对齐。
  • 用同一组测试题训练路由器再评价自适应收益。
消融、负结果与已有论文的关系
  • SFT only / SFT→OPD / SFT→RL / SFT→OPD→RL，匹配总训练成本。
  • FKL / RKL / AKL：固定 prefix 采样方式、教师与模式比例，区分即时终点与 RL 终点。
  • 模式损失分离 on/off；记录模式坍塌及控制 token 梯度。
  • 成本系数 λ=0 与多个 λ；预算条件输入 on/off；硬 cap 与学会自然停止分开。
  • easy/hard/混合；G=4/8/16 在相同总 rollout token 预算下比较，不只等 steps。
  • 不丢短错 / mask短错；检验是否因丢负例而学到短答捷径。
  • Teacher-compatible 预热 vs 能力相近但来源不同教师；总生成和预热成本均计入。
  • 可选压缩后验证：量化同一个学生，重测路由校准与质量—延迟曲线；不是两周最小实验的必选项。

应该接受的负结果

  • 若 OPD 初始分数提高、RL 后无额外收益，说明准备阶段指标与可学习性未一致，需要查看覆盖、熵与模式偏差。
  • 若 token 下降但 p95 延迟不降，分析长尾与调度；不能把 token 收益包装为系统加速。
  • 若 adaptive 仅优于固定差预算、但输给调好的 router/插值，贡献需转向机制分析或更低训练成本。
  • 若错误组/截断主导，先修数据与 verifier，再调 loss；无有效 reward 的训练不支持能力结论。

Simple-OPD 提供教师兼容预热视角；AKL 提供局部损失比较；MI/Timber 提供无需新训练的取舍与探索对照；量化系列提供真实成本和鲁棒性评估。这里只提出组合假设，没有引用任何论文证明整条流水线已有效。

三个小实现：手算结果比背代码更有用

练习 A · 组内优势与 mask

实现 G 个回报的组内标准化，组内方差使用总体方差；回报与优势 detach。给出 padding mask 下 token log-prob 的 sum 与 mean 两种归约。

R=[1,1,0,0] → mean=0.5, std=0.5 → A≈[1,1,−1,−1] R=[1,1,1,1] → A=[0,0,0,0]（仅结果奖励，无额外项） logp=[−1,−2,−3], mask=[1,1,0] → sum=−3, mean=−1.5

明确 epsilon、EOS 与截断处理；全 padding 样本应跳过或报错，不能静默制造有效样本。PyTorch 的 std 默认修正项可能与这里的总体方差口径不同，实现时显式指定。

练习 B · 学生前缀上的 FKL / RKL

固定同一批学生生成前缀，对教师与学生 logits 用 log_softmax，教师分布 detach。按完整词表计算两个 KL，区分温度变换、损失 mask 与长度归约。

p=student=[0.5,0.5], q=teacher=[0.75,0.25] FKL=KL(q‖p)≈0.130812 nats RKL=KL(p‖q)≈0.143841 nats p=q 时两者均为 0

检查非负性、词表维度、teacher 是否得到梯度；若只保留 top-k 或只抽一个 token，说明它近似了什么，不能仍把结果当完整 KL。

练习 C · 一张诚实的质量—成本图

  • 构造“平均 token 下降但困难题准确率大降”的样例，确认报表能看见退化。
